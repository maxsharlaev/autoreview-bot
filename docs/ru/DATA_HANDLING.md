# Обработка данных

Что сервис отправляет провайдеру модели, что хранит и как это удалить. Правила для публичных репозиториев: [PUBLIC_DISCLOSURE.md](PUBLIC_DISCLOSURE.md). Модель безопасности: [SECURITY.md](../../SECURITY.md).

<!-- section: sent-to-the-model-provider -->
## Отправляется провайдеру модели

Вызовы модели идут через Codex CLI с API-ключом owner'а прогона (`OPENAI_API_KEY` или `OWNER_<ID>_OPENAI_API_KEY`).

**Ревью кода** (`prompts/review.md`): промпт содержит имя репозитория, номер PR, ветку, base/head SHA, заголовок и тело PR, diff изменённых файлов (каждый файл обрезается по `codex.max_file_bytes`), замечания прошлых прогонов по этому PR и текст задачи Jira, если она связана и доступна для чтения. Codex работает **в склонированном checkout** с read-only песочницей, поэтому агент может прочитать любой файл head PR и включить его в контекст модели.

Diff, не попадающие в промпт:

- lockfile'ы: `package-lock.json`, `yarn.lock`, `pnpm-lock.yaml`, `poetry.lock`, `Cargo.lock`, `composer.lock`, `go.sum`;
- файлы `.env*`;
- по суффиксу: изображения (`.png`, `.jpg`, `.jpeg`, `.gif`, `.webp`, `.ico`), PDF, архивы (`.zip`, `.gz`, `.tgz`), шрифты (`.woff`, `.woff2`) и скомпилированные бинарники (`.exe`, `.dll`, `.so`, `.dylib`).

Другие сгенерированные, минифицированные или vendored-файлы (например `.min.js` или `.map`) не распознаются и отправляются как исходный код.

**Заголовок/описание PR** (при `pr_description.enabled`): заголовок и тело PR, имя ветки, до `pr_description.max_commit_messages` сообщений коммитов, сводка diff и текст задачи Jira.

Не отправляется: креды GitHub, Jira, Slack и базы данных агенту ревью не передаются (песочница получает минимальное окружение, см. [ENVIRONMENT.md](ENVIRONMENT.md)), как и данные Slack и данные других owner'ов. Ключ модели присутствует в окружении агента, потому что он нужен агенту для вызова модели; см. [SECURITY.md](../../SECURITY.md). Дайджест модель не вызывает.

Для публичного репозитория модели ревью и текста PR не получают текст задачи Jira; его получает отдельная read-only проверка соответствия, которая публикует только фиксированный результат ([PUBLIC_DISCLOSURE.md](PUBLIC_DISCLOSURE.md#jira-jira_disclosure)). Хранение на стороне провайдера определяется вашим договором с ним.

<!-- section: stored-in-postgres -->
## Хранится в Postgres

| Таблица | Содержимое |
| --- | --- |
| `repositories` | Полное имя, owner, идентичности авторов комментариев. |
| `pull_requests` | Номер, URL, заголовок, заголовок бота и хеш его источника, автор, исполнитель, состояние, SHA, head-ветка, ключ задачи, флаги draft/fork. |
| `review_runs` | Триггер, SHA, статус, версии модели/промпта, длительность, коды ошибок/пропусков, ARQ job id, JSON summary, URL комментария, `has_sensitive_content`, учёт статуса прогресса. |
| `findings` | Серьёзность, категория, путь, строка, заголовок, сценарий, доказательства, рекомендация, видимость, уверенность, статус. Доказательства могут цитировать код. |
| `finding_transitions` | История статусов с доказательствами. |
| `task_snapshots` | Ключ Jira, статус Jira, предупреждение, был ли сделан комментарий или переход. Не текст задачи. |
| `digest_runs` | Учёт дайджестов. |

Токены GitHub и API-ключи в базе не хранятся.

<!-- section: redis -->
## Redis

Очередь ARQ: id и аргументы job (id прогонов, репозиторий, номер PR) и короткоживущие результаты. Не источник истины.

<!-- section: temporary-files -->
## Временные файлы

Worker клонирует head PR во временный каталог (`ai-review-*` в системном временном каталоге, `TMPDIR`) и удаляет его по окончании прогона. Codex запускается с `--ephemeral`.

<!-- section: logs -->
## Логи

Сервис пишет логи в stdout: id прогонов, репозитории, номера PR, статусы, коды ошибок и короткие тексты ошибок. Токены намеренно не логируются. Срок хранения определяет ваш конвейер логов.

<!-- section: retention-and-deletion -->
## Хранение и удаление

Автоматического срока хранения нет: строки остаются, пока вы их не удалите. Sticky-комментарии, check run'ы и заголовки PR, записанные в GitHub, остаются в GitHub.

Чтобы удалить данные одного репозитория, удалите его строки в порядке зависимостей (`finding_transitions`, `findings`, `task_snapshots`, `review_runs`, `pull_requests`, `repositories`), предварительно сделав резервную копию. `digest_runs` не связана с репозиториями: JSON каждой строки перечисляет PR нескольких репозиториев (репозиторий, номер, URL, исполнитель, head SHA), поэтому удалите строки дайджеста этого owner'а за нужный период или перепишите их содержимое. Копии вне базы (комментарии и статусы GitHub, комментарии Jira, сообщения Slack, логи, резервные копии) удаляются отдельно. Удаление owner'а из конфигурации не удаляет его строки. Чтобы удалить всё, удалите тома `postgres_data` и Redis (`docker compose down -v`).
