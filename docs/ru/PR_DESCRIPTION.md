# Черновик описания PR

Функция выключена по умолчанию. Бот публикует и сохраняет ревью **до** запуска необязательной генерации текста PR. Ошибка или таймаут этого шага не отменяет ревью и не публикует его повторно. Черновик строится из заголовка и ветки PR, сообщений коммитов, сводки файлов, текущего описания и доступной задачи Jira. При смене SHA публикация пропускается. Codex работает в sandbox только для чтения и не получает ключ GitHub для записи. Draft- и fork-PR пропускаются, поскольку основной процесс ревью их не обрабатывает.

```yaml
pr_description:
  enabled: true
  mode: comment # comment | fill_empty | append
  title_mode: "off" # off | until_human_edit | when_invalid_or_inconsistent
  check_title_relevance: true
  timeout_seconds: 180
  max_commit_messages: 250
  prompt_file: "" # необязательно: prompts/local/pr_description.md

pr_text:
  language: auto # auto или код языка; если не задано — language.details
```

| Режим | Поведение |
| --- | --- |
| `comment` | Отдельный обновляемый комментарий с маркером `<!-- autoreview-bot:pr-description -->`. Автор может скопировать текст. |
| `fill_empty` | Заполняет пустое описание или неизменённый стандартный шаблон PR. При следующих запусках обновляет только нетронутый блок бота. |
| `append` | Добавляет помеченный блок после текста автора и обновляет только этот блок. |

Блок описания и комментарий с предложением содержат контрольную сумму текста бота. Если человек их изменил, бот не перезаписывает правки. В режиме `fill_empty` текст автора вне блока также останавливает обновление. Перед записью worker повторно читает тело и SHA PR. GitHub API не даёт атомарной проверки изменений в момент записи, поэтому одновременное редактирование в последнем промежутке остаётся ограничением.

`title_mode` управляет заголовком независимо от режима описания. `off` ничего не меняет. Два других режима вправе менять только пустой заголовок, заголовок, совпадающий с веткой, или собственный заголовок бота. `until_human_edit` обновляет его при изменении исходных данных; `when_invalid_or_inconsistent` дополнительно требует заглушку или явное несоответствие коммитам. Заголовок `Dev`, написанный человеком, сохраняется, а проблема показывается в разделе **Проверка заголовка**. Старое значение `always` принимается как устаревший алиас `until_human_edit` с предупреждением в логе. Бот хранит свой заголовок и хеш исходных данных в БД: нужна миграция `002_bot_title`. Предложенный заголовок должен соответствовать `type(scope)?: subject`, сохранять Jira-ключ исходного заголовка и не содержать управляющих символов или URL. Перед записью бот перечитывает заголовок и SHA; гонка в момент последнего запроса всё ещё возможна.

Шаблон ищется в `.github/`, корне репозитория и `docs/` на базовой ветке PR (`pull_request_template.md` или `PULL_REQUEST_TEMPLATE.md`), а также среди Markdown-файлов в `.github/PULL_REQUEST_TEMPLATE/`. Заменяется только точное совпадение после нормализации переводов строк и внешних пробелов.

Исходный промпт — [`prompts/pr_description.md`](../../prompts/pr_description.md). Для переопределения скопируйте его в `prompts/local/pr_description.md` и задайте `pr_description.prompt_file` в `config.yaml`. Каталог не попадает в Git и Docker-образ, но монтируется в worker только для чтения. Содержимое файла читается при следующем ревью; изменение YAML требует перезапуска worker. Сохраните в своём промпте требования к JSON и недоверенным данным. Пользовательский промпт должен выдавать текущую схему, включая `output_language` и поля оценки заголовка.

JSON проверяется по [`schemas/pr_description_output.json`](../../schemas/pr_description_output.json). HTML и упоминания экранируются, голые URL не становятся ссылками, пустые разделы опускаются. Без Jira нет раздела связанной задачи. `pr_text.language: auto` определяет английский или русский по заголовку человека, затем его описанию, затем коммитам; при нехватке текста используется `language.details`. Можно указать другой код языка для текста и subject заголовка. Названия разделов фиксированы для английского и русского, для остальных языков используются английские названия. Вывод на английском и русском проверяется по письменности и заявленному моделью языку; для других кодов выполняется отдельная проверка языка через Codex в sandbox только для чтения. При несовпадении бот повторяет генерацию один раз и затем пропускает публикацию. Тип и scope conventional commits остаются английскими. `max_commit_messages` ограничивает промпт и явно помечает усечение. GitHub ограничивает PR commits API 250 коммитами; если в метаданных PR коммитов больше, черновик тоже помечает список как усечённый.
