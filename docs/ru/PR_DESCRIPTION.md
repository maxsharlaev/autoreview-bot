# Черновик описания PR

Функция выключена по умолчанию. После успешного ревью бот составляет черновик из заголовка и ветки PR, сообщений коммитов, сводки изменённых файлов, текущего описания и доступной задачи Jira. Если SHA PR изменился во время генерации, публикация черновика пропускается. Codex работает в sandbox только для чтения и не получает ключ GitHub для записи.

```yaml
pr_description:
  enabled: true
  mode: comment # comment | fill_empty | append
  title_mode: "off" # off | always | when_invalid_or_inconsistent
  check_title_relevance: true
  prompt_file: "" # необязательно: prompts/local/pr_description.md
```

| Режим | Поведение |
| --- | --- |
| `comment` | Отдельный обновляемый комментарий с маркером `<!-- autoreview-bot:pr-description -->`. Автор может скопировать текст. |
| `fill_empty` | Заполняет пустое описание или неизменённый стандартный шаблон PR. При следующих запусках обновляет только нетронутый блок бота. |
| `append` | Добавляет помеченный блок после текста автора и обновляет только этот блок. |

Блок описания и комментарий с предложением содержат контрольную сумму текста бота. Если человек их изменил, бот не перезаписывает правки. В режиме `fill_empty` текст автора вне блока также останавливает обновление. Перед записью worker повторно читает тело и SHA PR. GitHub API не даёт атомарной проверки изменений в момент записи, поэтому одновременное редактирование в последнем промежутке остаётся ограничением.

`title_mode` управляет заголовком независимо от режима описания. `off` не меняет заголовок; `always` применяет корректный вариант, подтверждённый содержимым изменений; `when_invalid_or_inconsistent` заменяет заглушку (например, `Dev`), название ветки вместо заголовка или явное несоответствие заголовка сообщениям коммитов. При оценке `uncertain` заголовок из-за несоответствия не меняется. `check_title_relevance` включает сравнение с заголовками и телом коммитов; если его выключить, условный режим всё ещё находит заглушки и названия веток. При включённой проверке неустранённое несоответствие показывается в разделе **Проверка заголовка** черновика. Бот пропускает пустые и небезопасные варианты, повторно читает заголовок и SHA перед записью. Одновременное редактирование в момент последнего запроса всё ещё может вызвать гонку.

Шаблон ищется в `.github/`, корне репозитория и `docs/` на базовой ветке PR (`pull_request_template.md` или `PULL_REQUEST_TEMPLATE.md`), а также среди Markdown-файлов в `.github/PULL_REQUEST_TEMPLATE/`. Заменяется только точное совпадение после нормализации переводов строк и внешних пробелов.

Исходный промпт — [`prompts/pr_description.md`](../../prompts/pr_description.md). Для переопределения скопируйте его в `prompts/local/pr_description.md` и задайте `pr_description.prompt_file` в `config.yaml`. Каталог не попадает в Git и Docker-образ, но монтируется в worker только для чтения. Содержимое файла читается при следующем ревью; изменение YAML требует перезапуска worker. Сохраните в своём промпте требования к JSON и недоверенным данным.

JSON проверяется по [`schemas/pr_description_output.json`](../../schemas/pr_description_output.json). Разделы выводятся как обычный текст с экранированием HTML и упоминаний. Заголовки следуют `language.details` (`en` или `ru`). Без доступной Jira раздел связанной задачи опускается.
