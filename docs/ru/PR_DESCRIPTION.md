# Необязательные черновики описания PR

Английская версия: [PR_DESCRIPTION.md](../PR_DESCRIPTION.md). Все ключи: [CONFIGURATION.md](CONFIGURATION.md#pr_description).

Функция по умолчанию выключена. Она работает **после того, как ревью опубликовано и закоммичено**, и готовит описание PR из текущего заголовка, ветки, коммитов PR, сводки изменённых файлов, существующего тела и доступной задачи Jira. Сменившийся head SHA отменяет публикацию черновика. Таймаут или ошибка здесь не могут стереть или повторить завершённое ревью. Генератор использует Codex в read-only песочнице без кредов GitHub на запись; результат публикует только оркестратор. Draft- и fork-PR пропускаются, потому что поток ревью их исключает.

Для публичных репозиториев раздел Linked task управляется `public_repos.jira_disclosure`. Генератор описания и заголовка не получает текст задачи из Jira. `key_only` выводит ключ простым текстом, `none` его опускает, а `full` явно выводит summary и критерии приёмки Jira. См. [PUBLIC_DISCLOSURE.md](PUBLIC_DISCLOSURE.md).

```yaml
pr_description:
  enabled: true
  mode: comment # comment | fill_empty | append
  title_mode: "off" # off | until_human_edit | when_invalid_or_inconsistent
  check_title_relevance: true
  timeout_seconds: 180
  max_commit_chars: 12000
  language: auto # auto or any BCP 47 language code
  prompt_file: "" # optional: prompts/local/pr_description.md

size_guard:
  soft: {commits: 50, changed_lines: 5000}
  hard: {commits: 150, changed_lines: 20000}
  override_label: autoreview:force
```

| Режим | Поведение |
| --- | --- |
| `comment` | Публикует отдельное sticky-предложение с маркером `<!-- autoreview-bot:pr-description -->`. Автор может его скопировать. |
| `fill_empty` | Заполняет пустое тело или тело, точно совпадающее со стандартным шаблоном PR репозитория. Последующие обновления заменяют только неизменённый сгенерированный блок. |
| `append` | Добавляет явно помеченный сгенерированный блок под текстом автора и обновляет только этот блок. |

Сгенерированные блоки тела и комментарии-предложения хранят контрольную сумму текста бота. Если кто-то их редактирует, сервис их больше не трогает. В `fill_empty` добавление текста автора вне блока тоже останавливает автоматические обновления. Worker перечитывает тело и head PR перед записью; API обновления тела GitHub не даёт атомарного compare-and-swap, поэтому конкурентная правка в последнем окне запроса всё ещё требует осторожности.

Бот записывает в базу логин GitHub, который публикует sticky-комментарии (миграция `003_comment_authors`). После переключения с PAT на GitHub App или обратно он распознаёт комментарии, опубликованные ранее записанными идентичностями. Запустите обновлённого бота один раз со старыми кредами перед переключением; комментарии от идентичности, которую эта версия никогда не записывала, после переключения нельзя безопасно атрибутировать.

`title_mode` управляет изменением заголовка независимо от режима описания. `off` никогда не меняет заголовок. Оба режима записи меняют только пустой заголовок, заголовок, совпадающий с именем ветки, или заголовок, всё ещё равный последнему заголовку, записанному этим ботом. `until_human_edit` обновляет такие заголовки при изменении источника; `when_invalid_or_inconsistent` дополнительно требует заглушку или явное расхождение с заголовками и телами коммитов. Человеческий заголовок вроде `Dev` сохраняется, а его расхождение сообщается в **Title check**. `always` — устаревший алиас `until_human_edit`, он пишет предупреждение. Принадлежность боту и хеш источника хранятся в базе; нужна миграция `002_bot_title`. Предложение должно следовать `type(scope)?: subject`, сохранять ключ Jira из прежнего заголовка и не содержать управляющих символов или URL. Бот перечитывает заголовок и SHA перед обновлением. Конкурентная правка во время последнего запроса API всё ещё может столкнуться с обновлением.

Поиск шаблона проверяет `.github/`, корень репозитория и `docs/` в base-ветке PR (`pull_request_template.md` или `PULL_REQUEST_TEMPLATE.md`), а также Markdown-файлы в `.github/PULL_REQUEST_TEMPLATE/`. Заменяется только точное совпадение после нормализации переводов строк и внешних пробелов.

Промпт по умолчанию — [`prompts/pr_description.md`](../../prompts/pr_description.md). Чтобы его переопределить, скопируйте его в `prompts/local/pr_description.md` и задайте этот путь в `pr_description.prompt_file`. Каталог игнорируется Git и контекстом сборки Docker, но монтируется в worker только для чтения. Изменения файла читаются при следующем ревью; изменение `config.yaml` требует перезапуска worker'а. Сохраняйте в своих промптах правила «только JSON» и для недоверенного ввода. Свои промпты должны выдавать текущую схему, включая `output_language` и поля оценки заголовка.

Вывод проверяется по [`schemas/pr_description_output.json`](../../schemas/pr_description_output.json). Разделы выводятся простым текстом с экранированием HTML и упоминаний; голые URL разбиваются, чтобы не было автоматических ссылок. Пустые разделы и раздел связанной задачи без Jira опускаются. `pr_description.language: auto` определяет английский или русский по заголовку человека, затем телу, затем коммитам; при скудном вводе используется `language.details`. Явные коды языка передаются модели. Прежний ключ `pr_text.language` остаётся запасным для существующих установок. Другой код языка применяется и к subject заголовка. Заголовки разделов берутся из фиксированных английских/русских словарей, для других кодов языка — английские. Английский и русский вывод проверяется скриптом плюс заявленным моделью языком; для других кодов языка используется отдельная read-only проверка языка Codex. Расхождение вызывает одну перегенерацию, затем публикация пропускается. Тип и scope conventional commit остаются английскими. Бот не утверждает, что тесты прошли, без доказательств.

<!-- section: size-guard -->
## Size guard

Size guard использует итоги коммитов и строк PR из webhook до любого вызова модели. Если webhook не содержит этих полей или для ручного прогона, он использует метаданные PR, уже загруженные для ревью, без дополнительного запроса. Выше мягкого порога ревью выполняется, но генерация описания и заголовка пропускается. Выше жёсткого порога прогон пропускается с одним sticky-уведомлением; последующие push'и это уведомление не повторяют. Добавление метки `autoreview:force` запускает новый прогон в обход обоих порогов. Ровно на пороге PR всё ещё допускается.

<!-- section: commit-messages -->
## Сообщения коммитов

Промпт коммитов содержит только первую строку каждого полезного сообщения коммита, сгруппированную по conventional-типу. Сообщения fixup, squash, merge и WIP опускаются. `max_commit_chars` ограничивает выбранные заголовки; промпт указывает общее число и сколько коммитов не показано. Адаптер читает не больше 250 коммитов PR, которые отдаёт GitHub (`max_commit_messages`, по умолчанию 250, — legacy-ограничение этого числа).
