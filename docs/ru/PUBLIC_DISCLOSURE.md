# Раскрытие данных в публичных репозиториях

Worker при каждом прогоне подтверждает видимость репозитория через API GitHub. Видимость из webhook сохраняется как дополнительная консервативная подсказка. Отсутствующая или противоречивая видимость считается **публичной**. Приватные репозитории получают полный вывод ревью.

```yaml
public_repos:
  jira_disclosure: key_only # none | key_only | full
  security_findings: redact # redact | redact_all | full
```

Оба ключа можно переопределить для owner'а ([CONFIGURATION.md](CONFIGURATION.md#public_repos)).

## Jira (`jira_disclosure`)

Для публичного репозитория:

- `key_only` (по умолчанию) показывает ключ Jira простым текстом, без ссылки;
- `none` убирает связанный ключ из вывода бота;
- `full` явно разрешает содержимое связанной задачи (summary, критерии приёмки) в сгенерированном описании PR.

Модель ревью и генератор описания/заголовка PR не получают текст задачи из Jira для публичных репозиториев. Его получает отдельная read-only проверка соответствия, которая публикует только фиксированный результат: `matches`, `partial`, `mismatch` или `unknown`. Когда данные Jira доступны, это добавляет к каждому ревью публичного PR один вызов модели, задержку и стоимость.

## Замечания безопасности (`security_findings`)

При `redact` (по умолчанию) замечание редактируется, если его категория `security` или если его заголовок, сценарий, доказательства или рекомендация совпадают с ключевыми словами безопасности (injection, XSS, SSRF, CSRF, RCE, path traversal, deserialization, auth bypass, privilege escalation, secret, token leak, credential и подобные) или со ссылкой на CWE (`CWE-\d+`). Эвристика по ключевым словам не гарантирует, что будет поймано каждое неверно размеченное замечание; для строгих настроек используйте `redact_all`, который редактирует все замечания независимо от категории.

Отредактированное замечание показывает только серьёзность, путь/строку и общую подпись. В таблице переходов и заголовках карточек «Still open» отредактированное замечание сохраняет серьёзность и светофор ([комментарий ревью](PROGRESS_STATUS.md#комментарий-ревью)). Полные детали остаются в базе и уходят в настроенный комментарий Jira или канал Slack. Используйте приватный канал Slack, доступный только нужным ревьюерам. Если ни то ни другое не настроено, комментарий в PR сообщает, что детали скрыты.

`full` явно возвращает подробные замечания в GitHub, кроме деталей, записанных, пока репозиторий был приватным.

## Прошлые замечания

Прошлые замечания остаются доступными для отслеживания статуса. Детали замечаний, созданных, пока репозиторий был приватным (`details_visibility`), не попадают в контекст модели публичного прогона; детали, созданные, пока он был публичным, переиспользуются.

## Изменения видимости

Если повторная проверка приватной видимости перед публикацией не удалась или сообщает о публичном репозитории, прогон публикует общую безопасную для публичности версию, и тот же сокращённый текст уходит в Jira и Slack для этого прогона. Если head PR сменился, прогон падает с `HEAD_CHANGED`. Ранее опубликованные комментарии не переписываются.

См. также [DATA_HANDLING.md](DATA_HANDLING.md) и флаг `has_sensitive_content` в [PROGRESS_STATUS.md](PROGRESS_STATUS.md#has_sensitive_content).
