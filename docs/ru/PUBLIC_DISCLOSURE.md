# Раскрытие данных в публичных репозиториях

Worker проверяет видимость репозитория через GitHub API при каждом ревью. Видимость из webhook служит дополнительным ограничением. Если она неизвестна или данные противоречат друг другу, репозиторий считается публичным. Приватные репозитории сохраняют подробный формат вывода.

```yaml
public_repos:
  jira_disclosure: key_only # none | key_only | full
  security_findings: redact # redact | redact_all | full
```

Для публичного репозитория `key_only` показывает только ключ Jira обычным текстом, без ссылки; `none` убирает связанный ключ из текста бота. `full` явно разрешает публикацию содержания связанной задачи в описании PR. Основная модель ревью и генератор описания и заголовка не получают текст задачи, загруженный из Jira. Отдельная проверка соответствия задаче получает его, но публикует только фиксированный статус: `matches`, `partial`, `mismatch` или `unknown`. При наличии данных Jira это дополнительный вызов модели, время и стоимость на каждое ревью публичного PR.

Прошлые находки участвуют в отслеживании статусов. Подробности, созданные в приватном режиме (`details_visibility`), не передаются модели публичного прогона; подробности, созданные в публичном режиме, используются повторно.

При `security_findings: redact` (по умолчанию) замечания скрываются, если их категория — `security` или если в заголовке, сценарии, улике или рекомендации найдены ключевые слова безопасности (injection, XSS, SSRF, CSRF, RCE, path traversal, deserialization, auth bypass, privilege escalation, secret, token leak, credential и аналогичные) или ссылка на CWE (`CWE-\d+`). Эвристика по ключевым словам не гарантирует обнаружение всех неправильно классифицированных уязвимостей; для строгих конфигураций используйте `redact_all`, чтобы скрыть все категории замечаний. Скрытые замечания показывают только серьёзность, путь и строку, а также общее описание. Полные подробности сохраняются в базе и отправляются в настроенные каналы Jira и Slack. Для Slack используйте только приватный канал с доступом нужных участников. Если ни один из каналов не настроен, комментарий PR сообщает, что подробности скрыты.

Если повторная проверка приватности дала сбой или показала публичный репозиторий, в этом прогоне общий сокращённый текст отправляется также в Jira и Slack. При смене head прогон завершается ошибкой `HEAD_CHANGED`. `security_findings: full` явно разрешает подробные замечания в GitHub, кроме старых приватных подробностей. Ранее опубликованные комментарии не перезаписываются.
